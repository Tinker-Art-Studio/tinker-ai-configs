Plan: A guarded, verifiable way to deploy Cloud Functions to my-clay-hub (My Clay Hub Phase D2)

Goal: A Cloud Function reaches my-clay-hub only as the exact commit Christie approved, built from a clean checkout, after its tests pass. After every deploy the guard checks what is actually running against what the commit declares, and tests that no function answers a stranger. It leaves a record of every attempt that never claims more than it verified, even if the run is killed halfway.

F9The record of every attempt.
  1. Before the CLI is called, an in-flight file $GIT_DIR/tinker-deploy-inflight (project, codebase, sha, reserved stamp, folder tree id, "CLI invoked at <time>") is written and fsynced.
  2. After the read-back, whatever it found, an annotated receipt tag is written. It records cli_exit, backstop_seen=yes|no, deploy_match=yes|no|unknown, access=refused|answered|inconclusive, per-function state and hash, the folder tree id and the commit. verified=yes only when cli_exit=0, the backstop line was seen, deploy_match=yes and every endpoint was refused.
  3. Then the in-flight file is removed.
Reading the record:
  • The newest receipt is always the latest attempt. --status says "production verified at <sha>" only if that newest receipt is verified=yes. Otherwise it says "production may be mixed: the last verified deploy was X, and a later attempt at Y is not verified", in plain words.
  • --diff then shows the change from X, which may include changes Y already applied (a deliberate superset), under a banner naming Y.
  • An in-flight file, or a pending receipt, makes --approved refuse until --reconcile has run. --reconcile runs the read-back against that attempt's sha and writes its receipt.
verified= is read from the tag message by a fail-closed helper: a receipt it can't read stops the guard (EX_RECORD); it is never treated as unverified.		A functions release isn't all-or-nothing (K9). Every dimension is recorded separately, so the record never claims more than was checked. The in-flight file closes the gap between "production changed" and "a receipt exists".
