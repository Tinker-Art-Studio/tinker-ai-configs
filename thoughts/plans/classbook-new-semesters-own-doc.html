Plan: Classbook — every new semester gets its own document

Goal: When Christie creates Spring 2027 (and every semester after it), its lessons are stored in their own Firestore document, so the shared, size-capped curriculum/lessonData never grows again and lesson saves never hit the 1 MB wall.
Why now: Christie wants to build Spring 2027 the week of Oct 5, 2026. Today, "+ New Semester → Copy from Fall 2026" would write Spring 2027 into lessonData (44% → about 85%).
Parent plan: classbook-per-semester-lesson-storage.html (Phases A–C DONE: Spring 2026 lives in curriculum/lessons_spring-2026, verified). This plan is its required "Follow-up".
Scope for Oct 5 (revision 2): new weekly semesters are created — atomically, with their config entry — in their own document; one generic rule for new lessons_* documents; lessonData closed to new semester keys; reading, editing, live updates, counts and the gauge for any number of own-doc semesters; a production-shaped test seed. Trails it (before Spring 2027 is published): Studio Hub alerts. Deferred: deleting a semester that has its own document (Phase E), moving Fall (Phase D).
Touches: the Classbook (js/firebase-data.js, js/app.js, e2e/), studio-hub/firestore.rules + studio-hub/rules.test.js (sha phrase + guard), studio-hub/js/alerts.js. tinker-backups/backup.js needs no change (it already tallies every curriculum/lessons_* document, :388-392, and backs up the whole collection).

Until Phase B is live, do not create Spring 2027. If the deadline slips, wait — don't create it the old way. After Phase A alone, creating with "Copy from" is refused by the rules (nothing written).

Design (revision 2)

  • Flip the default. LEGACY_LESSONDATA_SEMESTERS = ['fall-2026'] replaces OWN_DOC_SEMESTERS. isOwnDocSemester(k) = isWeeklySemester(k) && !LEGACY_LESSONDATA_SEMESTERS.includes(k). Every new semester is own-doc with no flag and no per-semester code. The rules carry the same literal list.
  • Born own-doc vs moved. A semester has an edit pause only if storageMigrations has a record for it (Spring 2026: verified; Fall later). No record → editable as soon as its document exists. The pause/"missing" messages name the semester.
  • Create is one transaction (both reviewers). After updateAppData's two guards (config-load failure, registry error) and an empty-key refusal: one transaction reads appData and lessons_<key>; refuses if the key is already a semester; refuses with today's message if the document exists with real content and "Copy from" is chosen; adopts an existing document otherwise (no-copy path) or when it's template-empty; then tx.sets the document (slots or stamp only) and tx.updates semesters.<key> + stamps on appData. No compensation, no orphan, no read-to-update window. The rules check the pair with getAfter(appData).
  • lessonData is closed to new keys. A create or update may not add a top-level key outside ['fall-2026', 'lastUpdated', 'lastUpdatedBy'] (qaData already exists, so it stays editable without being listed; Fable 6). Existing keys change and disappear as today.
  • One generic rule block for new lessons_* documents: docId.matches('^lessons_[a-z0-9]+(-[a-z0-9]+)*$') && docId != 'lessons_spring-2026'. Spring 2026's literal rules stay exactly as deployed (Fable: saves the ~60-test rewrite; fold at Phase D). Create: manager+, only when getAfter(appData) lists the key as a semester. Update: manager+ or classbook roles, gated on a migration record if one exists (guarded exists first). Delete: manager+, only when the key is gone from the projected config or an unverified migration record exists (Phase D's undo). No routed delete in the app for Oct 5.
  • Deleting an own-doc semester stays disabled (Codex: stale-tab edits between backup and delete could be lost; Fable: two writes can strand a semester). One exception: a semester whose document is missing (only possible from a stale pre-deploy tab) can be deleted — config entry only, nothing to lose — so the "delete and create again" remedy works. Proper delete is Phase E.
  • Listeners by name. Map<semKey, unsubscribe> with a reconcileOwnDocListeners() that starts missing ones and stops removed ones; the lessonData listener carries every own-doc semester's map across each snapshot. createNewSemester calls reconcile only (no full listener re-setup, no generation bump). A vanished document for a semester without a migration record = "missing — deleted or changed elsewhere, reload", never writable. Initial load reads own docs in parallel.
  • Gauge: minimal — lessonData approx. size plus one line per own-doc semester with its approx. size (warn at 85%).
  • Slot template stays as today. See Decisions Log (Codex 5).
  • Studio Hub (trails the Classbook, before Spring 2027 is published): one listener on curriculum by document ID, >= 'lessons_' and < 'lessons_'; each snapshot replaces the own-doc map; only IDs matching the rules regex count; the semester key comes from the ID; two sources (legacy + range); keep the last complete map on error.
Why a legacy list and not a per-semester flag in config: a literal list can't flip under a bad or missing config read, and the rules use the same literal list without an extra get(appData) on every lessonData write.

Edge cases

  • Stale tabs (old code) after Phase A: Fall and Spring 2026 work as today. "Copy from" creation writes into lessonData → refused, nothing created. No-copy creation writes config only → Phase B code shows "storage is missing" with a working remedy.
  • Tabs open while Spring 2027 is created don't see it until they reload (config has no listener) — as today for any new semester.
  • appData missing entirely (defaults, which include spring-2026): own-doc listeners follow the defaults; no new semester can be created without appData's transaction read succeeding.
  • Growth: each tab listens to every own-doc semester (about 0.5 MB each, two more a year). Fine now; later, past semesters can be read once instead of listened to. A single semester near 1 MB: Spring 2026, the largest, is 54%; the gauge warns per semester at 85%.

Firebase safety checklist

  • Rules: no new collection — lessons_* are documents in curriculum. The generic rule is tested for every role and shipped through the guard with the sha phrase before any code relies on it.
  • Partial updates: lesson edits stay per-field dotted update()s; whole-semester writes stay set(…, {merge:true}); creation is a transaction set on a document just read inside the same transaction as absent (or template-empty/adopted), plus a dotted update of appData.
  • Empty fields: slot template unchanged (see Decisions Log); undefined is never written.
  • Awaited: the one create transaction is awaited before any UI change.
  • Snapshot before delete: no own-doc delete ships in this plan (Phase E). Backups: backup.js covers every lessons_* document.
  • Spot check: Phase C, in the Console.

If interrupted

  • After Phase A: apps behave as today; "Copy from" creation is refused (loud, nothing written). Don't create a semester until Phase B.
  • After Phase B: ready; Spring 2027 can be created. Its alerts reach Studio Hub only after Phase B′.
  • Mid-create: the transaction committed both writes or neither.
