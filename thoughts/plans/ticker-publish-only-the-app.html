The change (one phase, one commit)

Phase 1: build dist/ from committed files on a file-level allowlist, delete the four tools, gate and check every deploy

Acceptance (user outcomes):

  • The app works exactly as before after the deploy: sign-in, clock, schedules, time off, reminders, offline, install icons. All nine functions are still deployed, including the hourly reminder job.
  • Every path in the table above serves the app shell (or Netlify's own 404), never its content. This is checked on every deploy.
  • A new file is never published by accident. A new tracked file in the public-candidate set (js/**, css/**, assets/**, and root *.html, *.json, sw.js) makes the build refuse until it's listed as public or private on purpose. Any other file, e.g. a root notes.md, simply isn't in dist/, because only listed files are archived (round 1, both; wording narrowed per round 2, Codex M3).
  • Every published byte is a committed byte. Ignored or untracked files, e.g. .DS_Store, can't reach dist/.
  • Nothing is uploaded until a local preflight has passed and Christie has approved the exact sha (round 1, both).

Changes:

  • Delete user-import.html, grant-timeclock-access.html, schedule-import.html, summer-camp-sync.html (Christie, Sep 30). They stay in git history; summer-camp-sync.html is recoverable from f53788d for Summer 2027.
  • scripts/dist-private.txt: tracked files in the public-candidate set that are deliberately NOT published: firebase.json, package.json, package-lock.json (round 2, Codex B1: without this, the rule below refuses the current tree).
  • scripts/dist-manifest.txt: the file-level allowlist, one path per line, sorted: index.html, manifest.json, sw.js, the 2 css files, the 7 js files, the 6 asset files (all 16 APP_SHELL paths, sw.js itself, and both maskable icons; 18 files).
  • scripts/build-dist.sh: rm -rf dist && mkdir -p dist; then git archive HEAD -- $(cat scripts/dist-manifest.txt) | tar -x -C dist. That's committed bytes only, with no dot-files and no transformation. Then it refuses (exit 1, naming the file) if:
    • (cd dist && find . -type f | sed 's#^\./##' | sort) ≠ the sorted manifest (round 2, Codex L1);
    • the tracked public-candidate set (git ls-files filtered to the set above) ≠ manifest ∪ private list, or the two lists overlap ("list js/debug.js in dist-manifest.txt or dist-private.txt on purpose");
    • the completeness check fails: every local src/href in index.html, every sw.js APP_SHELL entry (/ → index.html), every manifest.json icon, and sw.js itself must exist in dist/. Fragment-only (#…), absolute (http(s):, //) and data:/mailto: values are skipped, and a query string is stripped (round 3, Codex L3).
    This runs before any upload. With the fallback, a missing app file would otherwise be cached by the service worker as HTML on every installed device (round 1, Claude M2). Comments in js/ are not grepped, e.g. auth-guard.js:15's example assets/logo.png (round 1, Claude M6).
  • scripts/preflight.sh (npm run deploy:check): the clean-tree guard, build-dist.sh, then npm test (full suite, emulator). It prints the sha and the exact approval sentence to ask Christie for. It never uploads. Claude runs it before asking "okay to deploy?" (round 1, Codex B2: build and test locally first).
  • scripts/deploy.sh (npm run deploy -- --approved <full sha>). It refuses, with a plain message, unless all of these hold:
    • --approved equals git rev-parse HEAD. Bare npm run deploy prints what would ship and stops (round 1, Claude M4);
    • the tree is clean;
    • the current branch is exactly main, its upstream is exactly origin/main (a missing upstream gets "push it first", not a git fatal), and after git fetch, HEAD == @{u} in both directions, neither ahead nor behind (round 1, Claude B2; round 2, Codex M1). So origin/main is exactly what's live.
    Then it re-runs the whole preflight (build + completeness + npm test) itself, so an approved sha can't be uploaded untested (round 2, Codex B2). Then netlify deploy --prod --dir dist --message "$SHA", then check-live.sh.
  • scripts/check-live.sh. Every request is curl -sS --location -o <fresh temp file> -w '%{http_code} %{content_type}' --connect-timeout 10 --max-time 30, with curl's exit code captured (round 3, Codex L1: no request can hang the check). Any transport failure (DNS, TLS, timeout, connection: non-zero exit) is fatal. The HTTP status is then compared with what that check expects (200, or an expected 401/403/404/405), and a body is hashed only on an expected 200. No --fail, so an expected 4xx isn't turned into a curl error; no set -e around probes (round 1, Codex M3; round 2, Codex M2). In order:
    1. Shell first: live /index.html must equal dist/index.html. On a mismatch, wait 15 s and retry once (this deploy changes index.html, so CDN lag is likely); if it still differs, stop with "private results unreliable" (round 1, Claude L1; round 3, Codex M1).
    2. Faithful: every manifest file is byte-identical live, and its media type (ignoring parameters like charset) is text/css for CSS, application/javascript or text/javascript for JS (including sw.js), and not text/html for any non-HTML file (round 2, Codex L2). Every mismatch, here and in the shell check, gets one real second attempt after 15 s (Claude L7; Codex M1). Every request carries a cache-busting query ?v=<sha>.
    3. Private: one explicit, checked-in list of concrete paths, scripts/must-not-be-public.txt (round 3, Codex L2): each path in the table (the four deleted pages kept forever as a memorial, notes, tests, firestore-debug.log, package*.json, firebase.json, deno.lock, netlify/functions/send-shift-reminders.js) must return a body equal to dist/index.html, or a 404. Anything else FAILS. Dot-paths aren't listed, because the CLI can't upload them.
    4. Functions, a positive signal for each (round 1, Claude B1: a missing function returns the shell with 200, so "not 404" proves nothing). GET, which sends nothing: preview-shift-reminders → 401 JSON (this also proves included_files resolved js/schedule-helpers.js); send-shift-reminders → 403 (a deployed scheduled function refuses HTTP); the other seven → 405 JSON. Verified live Sep 30.
  • netlify.toml: publish = "dist", with a comment. The site is not git-linked (checked Sep 30: no repo, no build command), so the CLI's --dir dist is what runs, and publish documents it. If it ever becomes git-linked, it needs command = "sh scripts/build-dist.sh" (round 1, Claude M5). The functions block is unchanged; functions and included_files resolve against the site root, not the publish folder (both reviewers verified).
  • .gitignore: add dist/; fix the comment that points at .netlifyignore. Delete .netlifyignore. It never worked, and its "verified" note was the fallback misread.
  • Docs: CLAUDE.md Deployment gets npm run deploy:check → ask → npm run deploy -- --approved <sha>, plus "netlify dev serves dist/; build first" (the http-server . line is unchanged). AGENTS.md:12's mention of "the standalone import pages" is updated, since they're gone (round 1, Claude L4).
  • Tests (source-level, no writes; the scripts themselves run in preflight): the manifest ⊇ APP_SHELL ∪ index.html refs ∪ manifest icons ∪ sw.js; the tracked public-candidate set (the same filter the build uses) == manifest ∪ private list, with no overlap; every manifest path is tracked; the four pages don't exist; deploy.sh enforces main/origin/main/HEAD==@{u} and re-runs preflight; netlify.toml publishes dist; deploy.sh requires --approved == HEAD plus the upstream/clean/pushed guards; check-live.sh compares bodies (never a bare status) for private paths and asserts each function's exact status.
Happy: preflight passes → Christie approves the sha → deploy → check-live ok: 18 files identical, private paths serve the shell, 9 functions answer as expected. The app signs in and works.
Edge: a stray js/debug.js is committed → build refuses: "js/debug.js is not in dist-manifest.txt". Nothing is uploaded.
Edge: a .DS_Store in assets/ → never archived (it's untracked) → nothing to report.
Edge (offline): an installed app on v24 → the next load installs v25 and caches all 16 shell files as their real types (completeness passed before upload; content types checked after).
Failure: bare npm run deploy, a wrong sha, a dirty tree, not on main, no upstream, ahead of or behind origin/main, or a failing test → a plain refusal before anything is uploaded.
Edge: the first build on today's tree (after the four deletions) → passes: firebase.json and the package files are in dist-private.txt.
Failure: check-live finds a mismatch, a leak, or a missing function → exit 1, naming it. The deploy is live, so the fix is to republish the previous deploy in Netlify's UI (instant), then investigate.
