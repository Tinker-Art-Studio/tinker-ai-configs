Plan: Ticker never lets a stored name or note run as code

App: Tinker Ticker (~/tinker-timeclock) · Drafted: Sep 29 2026 · v1 · execution-ready: false — waits for a design review and for Christie's written approval to edit the repo (Tinker Ticker rule).

Goal: a name, email, id or note stored in Firestore always shows up on screen as the text it is — including names like O'Brien and Jo "JJ" Smith — and can never add a click handler or script to a manager's page.

Source: Codex implementation review of ticker-sub-confirm-only-by-manager (Sep 29).

Scope: js/app.js, js/schedule-helpers.js (new pure encoders), tests. No Firestore write, no data shape change, no rules change, no new collection, nothing the Payroll Tool reads.

What is wrong

escapeHtml() (js/app.js:4502) is div.textContent = str; return div.innerHTML. That encodes & < > but not " or '. It is correct between tags and wrong in two other places app.js uses it:

ContextExampleWhat a stored " or ' does
A. quoted attribute<option value="${escapeHtml(e.name)}"> " ends the attribute; the rest becomes new attributes, e.g. onfocus=…. Stored XSS.
B. JS string inside an on…="…" handler onclick="removeEmployee('${emp.id}', '${escapeHtml(emp.name).replace(/'/g, "\\'")}')" " ends the handler attribute (XSS). ' is patched by the trailing .replace on some lines but not others; where it is missing, an apostrophe name breaks the button or ends the JS string.
Trap — the obvious one-line fix breaks apostrophe names. Making escapeHtml encode ' as &#39; fixes context A everywhere, but in context B the browser decodes &#39; back to ' before the handler runs, and the trailing .replace(/'/g, "\\'") no longer finds anything to escape. O'Brien would turn into a JS syntax error on the Remove / PIN / Merge / Assign buttons, which work today. HTML escaping alone can never be right for a JS string in an attribute; that context needs JS-string encoding, then HTML-attribute encoding. So both changes ship in one commit, and a wiring test pins it.

Design

  1. Two pure encoders in js/schedule-helpers.js (loaded as a browser global and require()-able by Jest): 
    // Text AND quoted-attribute safe. null/undefined → '' (what escapeHtml returns today).
function escapeAttr(v) {
  return (v == null ? '' : String(v))
    .replace(/&/g, '&amp;').replace(/</g, '&lt;').replace(/>/g, '&gt;')
    .replace(/"/g, '&quot;').replace(/'/g, '&#39;');
}
// A JS string literal for an inline handler, already attribute-encoded. Used WITHOUT surrounding quotes:
//   onclick="removeEmployee(${jsArg(emp.id)}, ${jsArg(emp.name)})"
function jsArg(v) { return escapeAttr(JSON.stringify(v == null ? '' : String(v))); }
    JSON.stringify escapes ", \ and control characters; the attribute encoding then survives the HTML parser, which hands the handler exactly the JSON literal back.
  2. escapeHtml becomes escapeAttr (same body, kept by name so the ~100 text-context callers don't change). Encoding quotes in text is invisible. Every context-A line is fixed by this alone.
  3. Every context-B handler switches to jsArg, dropping its hand-written quotes and any .replace(/'/g, …), including the raw '${emp.id}' / '${sched.uid}' args and the safeUid/safeName pair at js/app.js:2242 (whose .replace(/'/g, "\'") is a no-op — "\'" is just ' — so today an apostrophe name already breaks the ✏️ edit-entries button). Rule: no string goes into an on… attribute except through jsArg; numbers and locally built date strings may stay as they are only if listed in the test's allow-list with a reason.
  4. summer-camp-sync.html's own esc() gets the same quote encoding if the audit finds it used in an attribute.

Considered and not chosen: replacing inline handlers with data-* attributes and event delegation. It is the cleaner long-term shape, but it touches every handler's wiring in a 10k-line payroll file; jsArg is a mechanical, testable change to the same lines. The Sep 29 sub-confirm plan already builds its new checkboxes with DOM APIs, which is the pattern for new code.

Acceptance: a roster name with " or ' shows correctly everywhere and every button on that row still works; no stored value can add an attribute or handler.
