Firebase safety checklist

  • Every new collection (members, memberProfiles, staffRoster) gets an explicit rule and rules tests in the same commit as the code that writes it (E-2).
  • The only writer to my-clay-hub's member data is ingestMemberUpdate (a transaction; partial updates; never deletes; strips undefined/empty).
  • Nothing ever writes to tinker-hq-apps: clayhub-link@ holds read-only rights; tested in E-6 (a write attempt is refused).
  • Emulator tests only; no test reaches either production project; the CLI credential file is never read.
  • Bulk effect is bounded: reconcile and recompute stop above 10% status changes / 5% removals.
  • Vault gate before real data; the vault export keeps running weekly.

Completeness check — if it's interrupted

  • E-0…E-4 are code on branches: nothing live until merged and deployed.
  • E-5 halfway: Console state visible; re-read and continue. Nothing uses the accounts until E-6.
  • E-6 deployed but E-7 not: ingest is live with no callers except the probe — harmless.
  • E-7 deployed but E-8 not run: triggers send only members whose docs are edited; the projection is partial and nothing reads it (no sign-in until Phase F). The next 6-hourly reconcile fills it anyway.
