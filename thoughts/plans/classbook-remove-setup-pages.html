Recommendation: delete, don't fix

  • Fixing user-admin.html would mean maintaining a second user editor that has to track every new app key and role, which is exactly the drift that caused this bug. Manage Team already does the job.
  • The other four are one-time Feb 2026 bootstrap tools with hard-coded rosters. Running any of them today would regress real users, and nothing can make them safe except deleting them.
  • Git history keeps them recoverable (git show 5360e6d:user-admin.html).
Separate from the deletion, and Christie's call: several of these files contain plaintext temporary passwords for real staff accounts. They stay in git history (the repo is private) and were publicly served until Sep 25 2026. Deleting the files doesn't undo that. Recommended: in Firebase Console → Authentication, confirm that every account in those lists has changed its password since February, or send a reset. Rewriting git history isn't proposed (force-push to main is forbidden, and the Sep 25 exposure already happened).
