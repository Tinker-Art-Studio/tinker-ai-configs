Design

The data

  • Two optional fields on the camp's summerCamps_curriculum doc: reviewedAt (Firestore Timestamp) and reviewedBy (email via seasonActor()).
  • Not reviewed ⇔ carriedForwardFrom is set and reviewedAt is absent. Derived — so the 23 camps already in production need no backfill, and a camp created fresh in 2027 never shows the marker.
  • One helper, campReviewState(curriculumDoc) → 'unreviewed' | 'reviewed' | 'new', used by all four tabs, so the rule lives in one place.
  • Mark reviewed: Season.writeRef('summerCampsCurriculum').doc(id).update(Season.patch({ reviewedAt: now, reviewedBy })), awaited. Undo: same, with both fields FieldValue.delete() (pattern already used by saveBinInfo).
  • The label names the viewed season from the registry (seasonLabel(Season.viewing)) — nothing hard-codes "2027", so it works unchanged for 2028.

What people see

  • Curriculum card: while unreviewed, an amber Not yet reviewed for Summer 2027 badge replaces the grid status badge; the grey "Copied from Summer 2026" line stays. Once reviewed, the normal status badge returns and the grey line reads "Copied from Summer 2026 · reviewed Sep 28 by Christie".
  • Curriculum header: a count line when any copies exist — "23 camps copied from Summer 2026 · 23 not yet reviewed" — hidden when there are none.
  • Curriculum editor (a copied camp, current season, manager/admin): a band at the top — "Copied from Summer 2026 and not yet reviewed for Summer 2027. [Mark reviewed for Summer 2027]". After clicking: "Reviewed for Summer 2027 · Sep 28 by Christie · [Undo]". Read-only past-season view: the band shows the state but no button.
  • Lesson Plans, Project Details, Materials: the same amber badge next to the camp name in each tab's camp list/header. Display only — the button lives in one place (the editor).

Given a 2026 camp copied into 2027 (2027 current, manager) When Curriculum loads Then its card shows the amber not-reviewed badge, not the grid status, and the header reads "1 camp copied from Summer 2026 · 1 not yet reviewed".
Given that camp open in the editor When the manager clicks Mark reviewed Then the doc gains reviewedAt/reviewedBy, every other field is unchanged, the band shows Undo, and after closing the card shows its grid status and "reviewed … by …".
Edge — Given a reviewed camp When Undo is clicked Then both fields are deleted and the badge returns. Given an unreviewed copy When its grid is edited and auto-saved Then it is still unreviewed.

Carry-forward (emulator) — Given a 2027 curriculum with reviewedAt/reviewedBy When it is planned and copied into 2028 Then the 2028 doc has neither field and unknownFields is empty.
