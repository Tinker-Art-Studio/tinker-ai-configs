Design

The data

  • Two optional fields on the camp's summerCamps_curriculum doc: reviewedAt (Firestore Timestamp) and reviewedBy (the reviewer's uid — same key as window.STAFF_NAMES and sharedWith; rendered as STAFF_NAMES?.[uid] || 'a manager', escaped).
  • Not reviewed ⇔ carriedForwardFrom is set and reviewedAt is absent. Derived — so the 23 camps already in production need no backfill, and a camp created fresh in 2027 never shows the marker.
  • One helper, campReviewState(curriculumDoc) → 'unreviewed' | 'reviewed' | 'new', used by all four tabs, so the rule lives in one place. It accepts curriculum docs only (returns 'new' for anything without campTopic + blocks): carriedForwardFrom is also on copied topics, details and materials (carry-forward.js:169/177/195), and a rename copies it onto the new topic doc (camp-admin.js:206-215) — so no tab ever derives review state from its own records' provenance.
  • Mark reviewed: Season.writeRef('summerCampsCurriculum').doc(window.CURRICULUM_EDIT_ID).update(Season.patch({ reviewedAt: now, reviewedBy: uid })), awaited — addressed by doc id, never by campTopic (a rename mid-dialog must not write the wrong camp). Undo: same, with both fields FieldValue.delete() (pattern already used by saveBinInfo).
  • Who may: one predicate canReviewCamp() = role is admin or manager and Season.isViewingCurrent() — the same shape as canManageSchedule() (app.js:4009); not isSeasonAdmin(), which is admin-only, checked when rendering the button and again inside the handler. Staff and prep can open the curriculum editor today (no role gate on it, index.html:49/1123), so the button's own gate matters; the rule (update: if isManagerOrAbove(), verified at firestore.rules:829, no field allow-list) is the backstop.
  • Past-season view: the button's selector is added to PAST_SEASON_HIDE (app.js:~5634); Season.writeRef refuses anyway.
  • With the editor's saves: the button is disabled while its own write is pending (no out-of-order Mark/Undo), joins the editor's save-time disable list (app.js:~396), and its handler returns while curriculumManualSaving. Before writing, it flushes a pending auto-save — if curriculumAutoSaveTimer is set: clear it, queueCurriculumAutoSave(), then await curriculumAutoSaveChain. It must not call settleCurriculumAutoSave(): that cancels the pending save (app.js:361-365, safe only for Save, which then writes the whole form) and would silently drop the last 2 s of grid typing. A later auto-save is a partial update, so it can't wipe the fields.
  • No stale screen: on success the matching object in window.CURRICULUM_CAMPS is updated in place and the grid + header count are re-rendered immediately — not on the next tab load.
  • The label names the viewed season from the registry (seasonLabel(Season.viewing)) — nothing hard-codes "2027", so it works unchanged for 2028.

What people see

  • Curriculum card: while unreviewed, an amber Not yet reviewed for Summer 2027 badge replaces the grid status badge; the grey "Copied from Summer 2026" line stays. Once reviewed, the normal status badge returns and the grey line reads "Copied from Summer 2026 · reviewed Sep 28 by Christie".
  • Curriculum header: a count line when any copies exist — "23 copied camps · 23 not yet reviewed" — source-neutral, because a later summer can hold copies from more than one earlier summer (the copy dialog lets you pick any). Hidden when there are none. It is information, not a control: it shows for every role and in a past-season view, so it lives outside .curriculum-controls.admin-manager-only (index.html:73, hidden from staff/prep). Only the button is gated.
  • Curriculum editor (a copied camp, current season, manager/admin): a band at the top — "Copied from Summer 2026 and not yet reviewed for Summer 2027. [Mark reviewed for Summer 2027]". After clicking: "Reviewed for Summer 2027 · Sep 28 by Christie · [Undo]". Read-only past-season view: the band shows the state but no button.
  • Lesson Plans, Project Details, Materials: the same amber badge next to the camp name in each tab's camp list/header. Display only — the button lives in one place (the editor). Project Details and Materials attach it from the curriculum object they already render (by its id), never from child records (details/materials keep an old name after a rename, camp-admin.js:344). Lesson Plans adds a curriculum read outside its existing Promise.all (separately caught, defaulting to "no badges") and joins by exact topic.name === curriculum.campTopic; a duplicate name is logged, not guessed.
  • Coal Creek twins are separate camps with separate curriculum docs, so each is reviewed on its own. (Christie can say if she'd rather mark a pair together.)
  • All badge/name text is escaped (escapeSeasonText).

Given that camp open in the editor When the manager clicks Mark reviewed Then the doc gains reviewedAt/reviewedBy, every other field is unchanged, the band shows Undo, and after closing the card shows its grid status and "reviewed … by …".
Edge — Given a reviewed camp When Undo is clicked Then both fields are deleted and the badge returns. Given an unreviewed copy When its grid is edited and auto-saved Then it is still unreviewed.
Given the manager clicks Mark reviewed Then — without reload or closing — the header count drops by one; When Undo Then it rises again; closing the editor shows the card already updated.
Race — Given a grid cell typed less than 2 s ago (auto-save still pending) When Mark reviewed is clicked, then the page is reloaded Then the typed value and reviewedAt are both saved (catches a cancel-instead-of-flush). Given a manual Save in progress Then the button is disabled, and calling its handler writes nothing. Given Mark reviewed, then Save with the name unchanged Then still reviewed. Given a reviewed copy is renamed Then it stays reviewed.
Roles — Given current season, signed in as staff and as prep When a copied camp's editor opens Then the band's state and the header count are shown, the button is absent, and calling the handler directly makes no Season.writeRef call (spied — a rules denial alone must not be what makes this pass).
Past view with copies — Given 2028 registered and current, viewing 2027 (where copies exist) Then the badges and header count show, the button does not, and the handler makes no Season.writeRef call. A static check asserts the button's selector is in PAST_SEASON_HIDE. (The existing read-only sweep can't catch this: 2026 has no copies.)
Mixed sources — Given 2028 holds a copy from 2026 and one from 2027 Then the header reads "2 copied camps · 2 not yet reviewed" and each card's grey line names its own source.
Edge — Given a hand-made 2027 camp Then no badge, no band, not counted. Given viewing 2026 Then no button; a direct call is refused by Season.writeRef as read-only.
Failure — Given the write fails (offline / permission) When Mark reviewed is clicked Then an error is shown, the band still says not reviewed, and nothing claims success.
Carry-forward (emulator) — Given a 2027 curriculum with reviewedAt/reviewedBy When it is planned and copied into 2028 Then the 2028 doc has neither field and unknownFields is empty.

Completeness — what if it's interrupted?

  • Stopping between Phase 1 and 2 leaves a working app (Curriculum marked, other tabs as today) — but ship both together unless Christie asks otherwise.
  • Nothing is backfilled, so there's nothing to resume on the data side.
