The architectural insight that started this plan: three of the most severe findings share one root cause — saveSingleLesson() silently returns undefined instead of throwing when the global lessonDataLoadedSuccessfully guard is tripped. Fixing this one function to throw instead of silently returning closes several downstream findings as a side effect. Phase 1 below is that fix.

Phase 2 — SUPERSEDED: readAdminLessonDoc() is no longer needed by this plan

✅ Superseded by the round-3 atomic-write redesign (see Phase 9). This phase originally existed to force a server read of the move destination and verify its content actually matched what was written, BEFORE deleting the source — a safety net specifically needed because move did the destination write and the source delete as two SEPARATE, non-atomic Firestore operations. ✅ Superseded by the round-3 atomic-write redesign (see Phase 9). function buildLessonFieldUpdates(semesterKey, lessonKey, lessonData, fieldsToClear = []) {
  const clearedContentFields = fieldsToClear.filter(f => CONTENT_FIELDS.includes(f));

  for (const [field, value] of Object.entries(cleanData)) {
    updates[`${semesterKey}.${lessonKey}.${field}`] = value;
  }
  return updates;
