Design decisions

D1 — Entry identity: unique content-derived keys + value-based dedup, no migration (revised after review)

Key shapes (old keys untouched; old entries keep working):

SourceTodayAfter Phase 1
CSV uploadcsv::<camp>::<student>csv::<sessionId>::<campSlug>::<studentSlug>
Camp/SDOC scancamp::roster-N::roster-N-idxcamp::<sessionId>::<campSlug>::<studentSlug>
Workshop scanworkshop::workshop::ws-Nworkshop::<sessionId>::<studentSlug>
Semester scan (Phase 2)—semester::<sessionId>::<classSlug>::<studentSlug>
Summer scansummer::<weekId>::<studentId>unchanged
Manual addmanual::<ts>::<raw-name>manual::<ts>::<studentSlug> (slug strips punctuation — see B13)
  • Slugs strip everything but [a-z0-9] to -. No period, slash, tilde, asterisk or bracket can ever reach a key again. Keys built today may still contain them → B13 fix uses FieldPath objects for all patch/delete writes.
  • studentSlug = Sawyer Internal ID when present, else normalized name + (email or phone).
  • Immutable session identity. Every new entry stores sessionId (slug of the label at creation — never changes), session (display label — ✏️ rename edits only this), sessionDate (ISO; from weekStartDate / semesterEndDate / event-date prompt / import date), source, and internalId when known. Legacy entries lack these; helpers fall back to the label.
  • Dedup classification (pure function, tested) for each candidate against all existing entries:
    1. Identity match: if both sides have an Internal ID → IDs equal; else normalized name equal AND (email or phone equal when both sides have one; name alone when either side lacks contact info).
    2. Session match: existing sessionId equals candidate's, OR existing display label (normalized through formatPotterySessionLabel + slug) equals candidate's label slug. Handles "renamed then re-uploaded with either label".
    3. Identity + camp + session all match → already in this session → skip, and route through the name-guarded backfill (so legacy-key entries can pick up emails once B4 ships).
    4. Identity + camp match, session differs → returning → add.
    5. No identity match → new → add.
    6. Derived key already exists in the map: if that entry's normalized name matches → treat as (3), never suffix, never overwrite. If the name differs (true slug collision) → append ~2, ~3… and warn in console.
  • Backfill guard: backfillContact() only writes when the existing entry's normalized name matches the incoming student's, and writes each changed field as its own FieldPath patch — never the whole map.
  • Session labels are required and assisted. Import and manual add refuse an empty session. Both the session and camp inputs get a <datalist> of existing labels. The pending panel shows "N new · M returning · K already in this session" before the Import button is pressed.
  • Sanitizer (one function, tested): drop undefined and ''; keep null (it means "explicitly cleared" and is what update() needs to clear a date).
  • Pure module: js/pottery-identity.js — dual export (browser global + module.exports when module exists) so node --test can load it.

D2 — Pottery-only role mirrors the Coal Creek director pattern (revised after review)

  • New app-access key pottery-pickup. isPotteryOnly = hasAccess('pottery-pickup') && !hasAccess('roster-manager') && role ∉ {admin, manager}. Precedence: roster-manager (full app) > coal-creek-signin (existing CC lockdown) > pottery-pickup.
  • Pottery-only session: mode toggle, other tabs, Export/Print dropdowns, Settings link hidden; Scan button hidden; Help visible; templates visible and editable.
  • Init for pottery-only: skip loadDataFromFirestore() and restoreWorkingState(); the _potteryFromCache toast must still fire (do not copy the CC early-return that skips it).
  • Rules — two additive matches (no delete; entry removal is an update()):
    match /rosterManager/pottery { allow read, create, update: if hasAppAccess('pottery-pickup') && belongsToStudio('tinker'); } match /rosterManager/potteryTemplates { allow read, create, update: if hasAppAccess('pottery-pickup') && belongsToStudio('tinker'); }
  • Studio Hub: add { id: 'pottery-pickup', name: 'Pottery Pickup (Roster Manager tab only)' } to MANAGER_ONLY_APPS, and make the Roster Manager tile visible to that key — registry entry gains altAccess: ['pottery-pickup'], canAccessApp() treats any altAccess key as an override. (Extending the same to coal-creek-signin is a one-line follow-up if Christie wants the CC director to have a tile too — not in this plan.)
  • Security promise is scoped to cloud data. Firestore rules stop the pottery person reading rosters from the server. Same-origin localStorage from a previous full-access session on a shared device is not protected by rules; pottery-only init doesn't read it, but it isn't wiped either. Onboarding note: use their own login on their own device.

D3 — Pottery detection: Clay Hub venue first, keywords as fallback

Christie confirmed everything at Clay Hub is pottery. isPotteryActivity() returns true when the roster's venue is clayhub (Camp), the class location resolves to Clay Hub (Semester), the summer camp's venue is Clay Hub, or the activity name matches CONFIG.potteryKeywords (defaults: fired up, teen pottery, teen ceramics, pottery, ceramic, wheel, clay — covers workshops, which have no venue field). Keywords editable in Settings.

D4 — Two-person write safety (Phase 3)

  • Inserts stay set(newEntriesOnly, {merge:true}) — field-level for new keys and create-safe when the doc doesn't exist. update() on a missing document throws.
  • Mutations of existing entries (single field, bulk apply/clear, rename, checkboxes, notes) go through one helper: runTransaction → read rosterManager/pottery → drop patches whose entry key is no longer present → update() with FieldPath objects → on success replace state.potteryPickup with the fresh server map + applied patches, so a stale tab converges instead of drifting. No chunking: the 500 limit is for field transforms, not update-mask fields; one update is atomic.
  • Templates: per-key update() via the same helper on potteryTemplates, create-safe fallback to set(merge) if the doc is missing; failures surface as the red toast.
  • Local dates: a todayLocalISO() helper replaces toISOString().split('T')[0].
