Design (v2)

  1. Delta, not snapshot (D6). Each rendered checkbox records whether it was ticked when the card was drawn (data-initial). On Save, the change is only what the user toggled: added = boxes unticked at render and ticked now; removed = boxes ticked at render and unticked now. The new appAccess = fresh stored list (read in the transaction) − removed + added, de-duplicated, keeping the stored order. As a result:
    • ids with no checkbox (T2) are untouched;
    • a grant another tab added or removed after the card loaded is untouched unless Christie toggled that same box;
    • a card with no checkboxes (admin/manager) writes no appAccess at all (T1).
    Pure helper: computeAppAccess(fresh, boxes), where boxes is null or [{id, checked, initial}], and it returns undefined = don't write.
  2. New file js/team-helpers.js, the same pattern as js/archive-helpers.js (no DOM; a browser global plus module.exports):
    • KNOWN_ROLES = ['admin','manager','staff','prep']. 'prep' gets staff-style checkboxes (D5).
    • buildTeamMemberUpdate({role, studios, name, fresh, boxes}) returns {updates}, or {error} for an unrecognised role.
    • roleSelectOptions(storedRole): the four roles. An unrecognised or missing stored role adds a selected value="" "Unrecognised role (x) — choose one" placeholder, so nothing defaults to Admin. Saving with it refuses (T3).
    • escapeHtml() for every interpolated value (T5).
  3. saveUser(): one Firestore transaction that reads the user doc, computes the update from the fresh data, and calls transaction.update (partial, never set). A missing doc shows "This person no longer exists — reload". The roster add (addToTinkerTickerRoster) stays a separate step after it, as today (D10). It uses the final appAccess to decide on timeclock.
  4. Role-change re-render: staff-style boxes are redrawn from the stored-at-load grants, with initial = stored, so the delta is zero (T4). Unsaved ticks are lost when switching to admin/manager and back; this is documented.
  5. Hidden grants are shown read-only under the boxes ("Also has (not editable here): classbook-admin, team"), so nothing is invisible (D8).
  6. renderUserCard(): every field is escaped, and the inline onclick on Save/Archive/Reactivate is replaced by listeners bound to the card (T5).
  7. The duplicate private-events is removed. The team list sort is fixed so admins (roleOrder 0) sort first, not last (D11).
  8. createTeamMember(): the role list is unchanged (admin/manager/staff). Prep is edit-only in this branch (D9). Its success HTML escapes name and email.

Not changed: the KPI checkbox id (kpi-dashboard vs the rules' kpi) is a question for Christie (Q2), because renaming either side changes who has access.
