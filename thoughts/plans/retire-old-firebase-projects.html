Phase 3 — Lock both projects to deny-all execution-ready: false

Christie does, in the Console (a raw firebase deploy is blocked by the hook, and these projects aren't covered by the guard). Claude gives the exact text to paste:

  • clay-hub-inventory → Realtime Database → Rules: { "rules": { ".read": false, ".write": false } } → Publish
  • pimpneymouse-farm → Firestore → Rules: rules_version = '2'; service cloud.firestore { match /databases/{database}/documents { match /{document=**} { allow read, write: if false; } } } → Publish

Before publishing: Christie copies the current rules text (select-all in the Rules editor) into a note — the Console has no undo for rules. If Phase 1 found a Storage bucket, lock its rules too (allow read, write: if false;).

Deny-all stops any web/phone app from reading or writing. It does not stop an admin script with a service-account key — that's what Phase 1's service-account check is for.

(The ~/.claude/CLAUDE.md "never edit rules in the Console" rule is about tinker-hq-apps; these two projects have no rules file in any repo. Christie confirms this exception in the Decisions log.)

Phase 4 — Wait, then Christie deletes execution-ready: false

  1. Wait period — Christie picks (suggest 14 days). Claude records the date the wait ends in next-session.md.
  2. Christie deletes each in Console → Project settings → General → Delete project. This shuts the whole Google Cloud project down at once. The owner usually has a 30-day recovery window, but restoring is an emergency attempt, not a backup: Storage files can be deleted sooner and may not come back, and a restore can take up to 36 hours. After the window it's gone for good, and the project ID can never be reused. The saved copies from Phase 2 are the real safety net.

Done when: Christie has the shutdown confirmation, and Google Cloud console → Manage resources → "Pending deletion" lists both projects (with the date the 30 days end, recorded in next-session.md). projects:list dropping them isn't proof on its own.

Firebase safety checklist

  • Rules in studio-hub/firestore.rules updated? — No change needed; no new collection, tinker-hq-apps untouched.
  • Snapshot before a bulk/destructive op? — Yes: RTDB already in git (af6349a, verified identical today); farm Firestore saved first if non-empty.
  • Any Firestore write by Claude? — None. updateDoc/empty-field rules don't apply.
  • Codex review note: "no code under ~ references it" doesn't cover other computers, CI or third-party services — Phase 1's service-account/API-key check and the Phase 3 wait period cover that.
  • Credential file ~/.config/configstore/firebase-tools.json: never read. Only built-in read-only CLI commands (projects:list, apps:list, database:get, …); no hand-made REST calls.
  • Every destructive/outward step (rule publish, deletion) is done by Christie herself after she says so.
