What the research found

1. Existing holes in tinker-hq-apps: real, but no longer blocking this app. Members will never have accounts there. These are handed to the Backend Resilience plan's P2 item, "Tighten and test the Firestore/Storage rules" (step A6). They're still worth doing soon, because anyone with the public API key can create an account today.
  • Storage: every path trusts any signed-in account (read, overwrite, delete), and there are no Storage rules tests.
  • clayMembers self-create with isAdmin:true (firestore.rules:979-980): fixed by Phase A.
  • timeclock_settings/adminSubscriptions (:449) is readable by any account, and tinker-timeclock/netlify/functions/send-notification.js has no auth. Fixing that needs Christie's written approval (payroll gate).
  • isKiosk() (:40-46) trusts token.email. The fix is pinning the kiosk uids, not adding email_verified, which would lock the kiosks out.
  • Tinker HQ auto-creates a staff users doc for anyone who signs in (studio-hub/js/app.js:146-159, rule :127-132).
2. Membership Manager's data isn't shaped the way DATA-MODEL.md assumed (clay-hub-membership/js/app.js, js/firebase-data.js):
  • Collection and doc ID: the collection is clayHub_members. The doc ID is the email, lowercased, with . and / replaced by _ (firebase-data.js:54). The stored email field keeps its original case.
  • Status is stage: onboarding | touring | active | paused | offboarding | cancelled, plus a boolean isActive.
  • stage is only correct right after someone opens Membership Manager. Pause start and end, and offboarding → cancelled, are flipped by code that runs on page load (app.js:599-759).
  • Pause dates live in scheduledPause.{startDate,endDate} and pauseHistory[]. Last day is scheduledCancellation.finalAccessDate. All dates are YYYY-MM-DD strings.
  • Name is one name string. There's no first/last split.
  • No member-since field exists.
  • phone is free text, and it's blank for everyone imported from Sawyer.
  • Every Membership Manager page load re-writes every member doc in full (.set(), no merge, app.js:902). So nothing else may ever write to these docs, and the link's trigger fires for every member on every load. The link must compare only the fields it sends and skip unchanged ones.
  • Two Manager bugs (the resume check reads the oldest pause; "remove scheduled cancellation" leaves stage:'offboarding') are being fixed in a separate session started Sep 25.
3. The infrastructure the spec assumes doesn't exist yet.
  • No Cloud Functions anywhere. tinker-hq-apps is on Blaze (since May 28, with a $20 budget alert).
  • The deploy guard only ships rules, storage and indexes, for tinker-hq-apps only.
  • No app uses email-link or Google sign-in.
  • The spec's beforeSignIn blocking function needs the paid Identity Platform upgrade.
  • Tinker HQ doesn't host other apps' screens.
4. Clay Hub Booking's footprint is small.
  • Never deployed and linked from nowhere.
  • It left behind:
    • a rules block (firestore.rules:956-1003) for clayMembers, clayBookings, claySpots, clayBlockedSlots, claySettings
    • one index (firestore.indexes.json:2-20)
    • a registry row and a palette mention in product-principles.md (:177, :102)
    • a memory file and its index lines
    • mentions in two audit docs
  • Production may hold seeded claySpots, a clayMembers doc for Christie's uid, and Auth accounts that Booking created.

  • Active if stage is active, paused (outside any window) or offboarding (before the last day).
  • No access for onboarding or touring.
The link sends raw fields. The members project computes the status, and recomputes it for everyone nightly.
