**Verdict: SAFE TO DEPLOY.** No blocking defects in bbfccaa. Two low-severity follow-ups, neither needed before this ships.

**Checks that passed**

- **Switching the global semester right after create.** The creator is always admin or manager, since the New Semester button lives inside `#ca-semester-bar`, which only renders for those roles (app.js:4574, index.html:164). So `canSeeSemester` returns true for the new unpublished semester and `initGlobalSemesterSelector` keeps the key instead of resetting it (app.js:65). The new semester is weekly, so the Prep Dashboard tab stays visible and the early-return path in `setGlobalSemester` is not taken. Teacher view, settings and notices are untouched: the active tab is always Curriculum Admin when this runs, and the other tabs re-sync on entry (`initTeacherView`, `ensureSettingsFormMatchesHeader`). The paused-notice update is called twice (app.js:5079 and inside `setGlobalSemester`), harmless.
- **onchange vs the old listener.** Nothing else listens on `#global-semester-select`. The only document-level change delegate (app.js:8856) matches `.prep-checkbox` only. The Teacher View selector (app.js:857) sets the header's value and calls `setGlobalSemester` directly, so it never depended on the header's own listener. Tests use `selectOption`, which fires change and works with `onchange`. The CA selector already uses the same `onchange` pattern (app.js:4589).
- **Toast.** `textContent` with a user-supplied name, no HTML path. `role="status"` plus `aria-live="polite"` is correct. Slot count is right: `installOwnDocMap` runs the written doc through `ownDocLessonMap`, which strips the two stamp keys (firebase-data.js:124), so the count is slots only, not slots plus stamps.
- **Test.** The handler-stack check is valid: app.js is a classic script (index.html:588), so reassigning `window.setGlobalSemester` is picked up by the `onchange` closure's global lookup. The Fall fixture has 2 teacher/class combos times 2 weeks, so "4 lesson slots" is correct. The toast assertion runs within its 5 s window since `createSemester` resolves synchronously after the toast is shown.

**Findings (non-blocking)**

1. **app.js:5085–5094, post-write UI is unguarded.** The comment at app.js:4998 says every failure must be handled in this frame, but the try/catch covers only the write. If any of `setGlobalSemester`, `initGlobalSemesterSelector` or the six renders throws, the semester exists on the server, the modal is already closed, and the toast never shows, so the admin sees nothing and may try again (hitting the "already exists" refusal). `createDayOffYear` wraps the same stretch in try/catch with a "created, but the page didn't refresh, reload" alert (app.js:4815–4828). Pre-existing gap, but this commit lengthens it and moves the only success signal to the end. Suggest the same wrapper.
2. **app.js:5103–5114, live-region announcement.** The region is created and filled in the same tick on first use. Some screen readers skip announcing content that arrives with the live region itself. After the fade the text stays in the accessibility tree at opacity 0. Low-cost fix: clear `textContent` in the timeout, and either place the empty region in index.html or set text on the next frame.

Minor nit: with the Curriculum Admin tab active, `setGlobalSemester` already runs the six CA renders, so the explicit calls at app.js:5087–5092 are now redundant. Harmless.
