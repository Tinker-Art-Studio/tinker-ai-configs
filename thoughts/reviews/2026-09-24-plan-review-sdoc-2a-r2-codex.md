- **HIGH — Staff cannot Undo “Materials complete.”** Deployed rules permit Kathy/Allie (`classbook` + `curriculum-admin`) to create/update lesson documents but not delete them ([firestore.rules](/Users/christiehubley/studio-hub/firestore.rules:700)). Use an update-based tombstone such as `complete:false`/cleared metadata, or change rules.

- **HIGH — A bare generation bump can suppress a real load failure.** The existing generation gate allows only the current reload to update the load guard/banner ([firebase-data.js](/Users/christiehubley/tinker-spring-curriculum/js/firebase-data.js:1112)). Scenario: a reload starts, a material write succeeds and increments the generation, then another SDOC query in that reload fails. The failure is classified stale, so it cannot disable writes or show the banner, and no replacement reload is scheduled. Every bump must start/await a replacement generation-gated reload; do not increment the counter alone.

- **MEDIUM — “Header selector only” does not satisfy the promised visibility test.** Kathy/Allie already satisfy `hasCurriculumAdminAccess()`, and `renderTvSemesterSelector()` consequently includes **all** unpublished semesters ([app.js](/Users/christiehubley/tinker-spring-curriculum/js/app.js:693)). Plain teachers remain excluded; the manager-only CA selector remains unaffected.

- **MEDIUM — Transaction ordering/query mechanics need to be normative.** Compat Firestore 10.8 transactions require all document reads before any write and provide no query reads. Scenario: two renames implemented as “read pair → write pair” loops fail when the second pair is read. Require queries outside the transaction, derive deterministic refs, then `transaction.get()` every camp/plan/sign-off ref before performing any write. Apply this explicitly to camp save, sign-off, and camp removal.

Rebase changed cells onto the transaction-read camp, or refuse when the relevant server field differs from A’s opening snapshot.

The renamed fields, targeted map paths, transaction-read rename source/target, deterministic removal refs, sign-off separation from slots, `#` document ID, capability split, and both resolved review questions are otherwise sound.
