### Should-fix

**1. `--status` lists the wrong commits when the shared tree is on a branch — `scripts/deploy-rules.sh:109`**
`git log "$RC.." "$MAIN_SHA" -- "$FILE"` is two revision args: `RC..` expands to `RC..HEAD`, so the set is `{HEAD, origin/main} − ancestors(RC)`. Concrete: a session does what CLAUDE.md is about to recommend (`git checkout -b rules-x; edit firestore.rules; commit`), then `--status` prints that unpushed wip commit under "origin/main is AHEAD of the last receipt; commits touching firestore.rules" — a lie in the exact place the plan tells Christie to look. Invisible today (HEAD == main) and in the harness (HEAD == main throughout).
Change: `"$(receipt_commit "$RECEIPT")..${MAIN_SHA}"` (one range arg).

**2. `--status` right now says "AHEAD" with an empty commit list and offers a no-op deploy — `scripts/deploy-rules.sh:104-117`**
Real state: last receipt `…-1da12e3`, origin/main `b954495`, and `b954495` touches no `firestore.rules` (its stat is the 5 guard files). So the first thing Christie sees is `state: origin/main is AHEAD of the last receipt; commits touching firestore.rules:` followed by nothing, then "(run --diff …)" (empty diff) and the phrase for `b954495`. Not wrong, but it reads as "something needs deploying".
Change: before line 108, `if git diff --quiet "$RC" "$MAIN_SHA" -- "$FILE"; then say "state: ${REMOTE}/${BRANCH} is ahead of the last receipt but ${FILE} is unchanged since ${RC:0:12} — nothing to deploy for ${TARGET}"; else …` and have `--diff` print `(no change to ${FILE})` on an empty diff. (A deliberate no-op deploy of `b954495` is actually a good dress rehearsal — see #8 — but the status should say what it is.)

**3. The receipt describes `firestore.rules`, but what ships is whatever the commit's `firebase.json` maps — `scripts/deploy-rules.sh:59-64, 160-177, 194`**
The guard hardcodes `FILE` per target, prints the diff of that file, hashes that file — while firebase-tools ships `firebase.json`'s `firestore.rules` path from the same worktree. A commit on main whose `firebase.json` says `"rules": "rules/prod.rules"` (or drops `predeploy`) passes every check: `--diff` shows nothing/only the rules file, the receipt records `firestore.rules`'s sha256, and different bytes ship. That is the "approve a diff, not an act" hole: the pasted `--diff` is of one file, the act is defined by another. Same for a rollback to any pre-`b954495` commit: its `firebase.json` has no predeploy, so that path has no byte check at all (harmless in the guard's flow, but silent).
Change, after line 161:
```bash
case "$TARGET" in firestore:rules) KEY='.firestore.rules';; storage) KEY='.storage.rules';; firestore:indexes) KEY='.firestore.indexes';; esac
MAPPED="$(/usr/bin/jq -r "$KEY // empty" "$TMP/firebase.json" 2>/dev/null || true)"
[ "$MAPPED" = "$FILE" ] || die $EX_CONFIG "firebase.json at ${SHA:0:12} maps ${TARGET} to '${MAPPED}', not ${FILE}; the receipt would not describe what shipped."
/usr/bin/jq -e '.firestore.predeploy // .storage.predeploy' "$TMP/firebase.json" >/dev/null 2>&1 || warn "firebase.json at ${SHA:0:12} has no predeploy hook (pre-guard commit); shipping the commit's bytes without the byte-check"
```
(new `EX_CONFIG=18`), and in `--status`/`--diff` include `firebase.json` in the `-- "$FILE"` pathspec so a mapping change is in what Christie reads.

**4. A failed `git tag -a` after a successful deploy leaves no receipt, no distinct exit, and the next run does not know — `scripts/deploy-rules.sh:202`**
`git tag -a` can fail (no tagger identity in this environment, `tag.gpgSign` on with no key, disk). Under `set -e` that exits 128 with git's message, prints nothing about the deploy having succeeded, and — because there is no local tag — step 1 has nothing to reconcile, so the following run deploys again with no record of this one. That breaks "the record can never fall two deploys behind" via the one path exit 17 does not cover.
Change: wrap it: `git tag -a … || { printf 'DEPLOY SUCCEEDED; RECEIPT NOT WRITTEN.\nProduction is now %s. Create it by hand:\n  git tag -a %s %s -m "…sha256=%s…"\n  git push %s refs/tags/%s\n' …>&2; exit $EX_RECEIPT; }` (the message already has every field).

**5. Receipts on origin that the local repo lacks are invisible — `scripts/deploy-rules.sh:74, 79, 84`**
`git fetch origin main` uses a refspec with no dst, and in `builtin/fetch.c` `autotags` is only set when a refspec has a dst — so tags are never auto-followed by this fetch (this is the one I most wanted to run empirically; the check is in `exp.sh` if you can run it). `latest_receipt` reads local tags only. So if another clone deploys (a cloud session, a second machine), or a local tag is accidentally deleted, `--status` names the wrong "last receipt", the printed "replaces:" diff is wrong, and the phrase offers re-deploying something already shipped. The guard even *knows* better — `REMOTE_TAGS` at line 137 lists them — and ignores them.
Change: in `fetch_main` and the status branch, add a second fetch: `git fetch --quiet "$REMOTE" "refs/tags/${TAG_ROOT}/*:refs/tags/${TAG_ROOT}/*" || die $EX_FETCH "a receipt on ${REMOTE} differs from the local copy or could not be fetched — receipts are immutable; look before deploying."` (no `+`: a moved tag on origin is then a loud refusal, which is what you want). This is an explicit namespace, still never `--tags`.

**6. `REMOTE_TAGS` failure is a silent exit 128 — `scripts/deploy-rules.sh:137`**
`VAR="$(pipeline)"` under `set -e` exits the script if the pipeline fails, and `2>/dev/null` swallows git's message — so a transient `ls-remote` failure (right after a successful fetch, but possible) exits with git's code and no sentence, violating "every refusal has a distinct code and one plain sentence". Cleanup does run.
Change: `REMOTE_TAGS="$(… | sort -u)" || die $EX_FETCH "could not list receipts on ${REMOTE}; fix the connection first."`

**7. The predeploy backstop's coverage is overstated — `scripts/predeploy-check.sh:3-7`, commit message, plan "The backstop"**
Bypasses that never touch studio-hub's `firebase.json`, so the hook never runs: (a) `firebase deploy --only firestore:rules --project tinker-hq-apps --config /tmp/fb.json` where the JSON has `"rules": "/Users/christiehubley/studio-hub/firestore.rules"` (absolute paths resolve; no predeploy key) — no firebase-tools flag *skips* a hook, but `--config`/`-c` replaces the file that declares it; (b) any other checkout/repo on this machine with a `firebase.json` naming a `firestore` section — the exact case the Aug 15 cwd-guard existed for, which Phase 2 retires as "inherent in the guard"; (c) editing `scripts/predeploy-check.sh` or `firebase.json` in the shared tree — the hook runs from the tree it ships from, so the untrusted tree can neuter it; (d) `firebase-admin` `securityRules()` with a service-account key (`.gitignore` lists `setup/service-account*.json`). None of these are fixable in the hook; they are fixable in the words. Change: the header and the plan should say the backstop covers "a deploy that reads this repo's firebase.json", and Phase 2's hook (which already denies every `firebase deploy` string, `--config` included) is what covers (a)–(c) — so do not describe the cwd concern as retired; it moved.

## Checked and found sound

- **Bash 3.2:** `[[ =~ ^[0-9a-f]{40}$ ]]` unquoted ERE, `${SHA:0:12}`, `local`, `$'\n'`, `<(…)`, BSD `mktemp -d` template (X's at the end), `date -u`, `shasum`, `xargs -I{}`. `set -e` interplay is right everywhere I looked: `[ -n "$D" ] && warn` is never the last command in its list; `if !` guards the grep-returns-1 pipes; `|| true` on `rev-parse`; `merge-base --is-ancestor` exit 1 caught by `||`.
- **trap/EXIT:** lock taken before the trap is installed, but nothing between can fail; `die` → `exit` runs the trap; bash runs EXIT on SIGINT; cwd stays `$REPO` because tests/deploy run in subshells, so `git worktree remove` resolves; cleanup is idempotent; every `$TMP`/`$REPO` use is quoted (a repo path with spaces works; `awk '{print $1}'` on shasum output is space-safe).
- **Worktree == `git show`:** no `.gitattributes`, no `.git/info/attributes`, no `.gitmodules`, no `core.autocrlf` in repo config, no stale `.git/worktrees`; and if global autocrlf were on, the harness's happy path would have failed on this machine. Private worktree + predeploy byte-check + nothing writes between → the receipt's sha256 is the bytes firebase-tools read.
- **Receipts:** fixed-width UTC names make `--sort=-refname` correct across mixed timestamps; slug in the name separates targets; the same-second collision loop is right; `ls-remote` parsing handles `^{}` and `ls-remote` exits 0 on no match; `git tag -l 'prefix/*'` cannot cross into `storage/`. Push is one explicit refspec, no force, no `--tags`.
- **Ancestor/sha checks:** full 40-hex, lowercased, resolved via `^{commit}` and compared back to the input; ancestor-of-`origin/main` after a real fetch, so the unpushed-local-main case is refused (14) and a rollback is allowed by design.
- **firebase-tools (from source as I know it, not opened here):** `filterTargets` maps `--only firestore:rules` → `firestore` via `opt.split(":")[0]`; `deploy/index.ts` pushes `lifecycleHooks(targetName,"predeploy")` per target and runs `chain(predeploys)` before `prepare`, `--dry-run` included; the hook runs with `cwd = config.projectDir` (the worktree root, where `bash scripts/…` resolves) and `env = process.env + GCLOUD_PROJECT…`, so `TINKER_DEPLOY_SHA` passes through; no deploy flag skips hooks (only `--config` swaps the file, #7). To confirm locally: `grep -n 'split(":")\[0\]' "$(npm root -g)/firebase-tools/lib/filterTargets.js"` and `grep -n 'lifecycleHooks(targetName, "predeploy")' "$(npm root -g)/firebase-tools/lib/deploy/index.js"`. The fake is faithful on cwd, env passthrough and non-zero → deploy fails; unfaithful only on hook selection (#14).
- **predeploy-check.sh:** `pipefail` makes a missing `sha:file` refuse; `cmp -s -` compares raw bytes; works inside a worktree (`.git` file); uppercase refused is fine since only the guard sets it.
- **Harness:** 71 assertions counted; `set -uo pipefail` without `-e` is correct for a test runner; `fixture_reset` clears local tags, origin tags, lock, pushurl and fakes; the wip-branch, dirty-tree, mutate-during-tests, 15/16/17→12→reconcile, lock and rollback cases match the plan's BDD lines; `package.json` wiring matches the plan.
